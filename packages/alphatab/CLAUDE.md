# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

This is the **alphaTab monorepo** (`@coderline/alphatab-monorepo`, npm workspaces under `packages/*`). The core library lives in `packages/alphatab`; everything else consumes it. You are usually working inside `packages/alphatab`.

Key sibling packages:
- `packages/alphatab` — the rendering/synthesis engine (this package).
- `packages/transpiler` — TypeScript → C# / Kotlin source transpiler. Parses `src/` with the TS compiler and emits cross-platform code. Run via `generate-typescript`.
- `packages/tooling` — shared Vite build plugins and TS helpers (`elementStyleUsingTransformer`, `dtsPathsTransformer`).
- `packages/csharp`, `packages/kotlin` — consume transpiled output to build native alphaTab.
- `packages/playground`, `packages/vscode`, `packages/lsp`, `packages/monaco`, `packages/vite`, `packages/webpack` — dev tooling and integrations.

Branches: `develop` is the integration branch; PRs target `develop`.

## Common commands

All commands below run from `packages/alphatab` unless noted. Run from the repo root to use the monorepo-level wrappers.

### Build
```bash
npm run generate-typescript   # regenerate src/generated/* (Cloner, Serializer, JSON decls, VersionInfo) — DO NOT hand-edit generated files
npm run build                 # generate-typescript + vite build (ESM) + vite build (UMD)
npm run typecheck             # tsc --noEmit
npm run lint                  # biome lint
```
Build outputs go to `dist/`. The build copies `font/bravura/*` and `font/sonivox/*` into `dist/font` and `dist/soundfont`.

### Test
```bash
npm test                              # mocha (loads .env, runs test/**/*.test.ts via tsx)
npm test -- --grep "pattern"          # run a single test by name
npm test -- --grep "AlphaTexImporter" # run one test file's suite
UPDATE_SNAPSHOT=true npm test         # update jest snapshots (also: --updateSnapshot)
CI=true npm test                      # CI mode: snapshots are write-locked (update disabled)
```
`.mocharc.json` injects `test/global-hooks.ts` (sets up chai + jest-snapshot) and uses `tsx/esm` with `experimental-specifier-resolution=node`. Imports use the `@coderline/alphatab` package name (resolved via workspace), **not** deep relative paths — see the import style note below.

### Visual / reference tests
Visual tests render to a Skia canvas and pixel-compare against `.png` reference files in `test-data/visual-tests/`. On mismatch, the helper writes `<name>.new.png` and `<name>.diff.png` next to the reference. These artifacts are gitignored.
```bash
npm run test-accept-reference   # promote all *.new.png → *.png and delete *.diff.png (use after verifying a deliberate change)
```
Only run/accept visual references for rendering changes you intend to change; an unexpected `.new.png` means your change altered rendering.

### Regenerating code
Any change to a model/settings class annotated with `@json` requires `npm run generate-typescript` to regenerate serializers under `src/generated/`. The generated files start with an `<auto-generated>` header.

## Architecture

### Cross-platform transpilation model (read before editing public API)
alphaTab is authored once in TypeScript and transpiled to C# and Kotlin. Two doc-comment annotations drive this and **must be respected**:
- `@target web` — marks members that are browser/Node-only (DOM, workers, audio worklets, `import.meta.url`). The transpiler **drops these from C#/Kotlin**; the TS build keeps them. When editing, treat `@target web` members as not existing on the native targets.
- `@partial` — marks a class whose declaration is split across multiple files (members merged by the transpiler). A `@partial` class in file A can have its members extended in file B. Do not collapse partial classes into single files.
- `@json`, `@json_strict`, `@json_on_parent`, `@json_partial_names`, `@json_add` — drive JSON (de)serialization codegen. `@json` classes get a generated `*Serializer` and `*Json` type in `src/generated/`. Adding/removing `@json` fields requires regenerating.

If you add a public class member, consider whether it needs `@target web` (browser-only) and whether its class is `@json` (then regenerate).

### Source structure (`packages/alphatab/src`)
- `model/` — the music notation domain model (`Score`, `Track`, `Bar`, `Beat`, `Note`, `Voice`, …). Pure data; the transpiler and serializers revolve around these.
- `importer/` — file format readers: `AlphaTexImporter` (+ `alphaTex/` parser/lexer), `Gp3To5Importer`, `Gp7To8Importer`, `GpxImporter`, `MusicXmlImporter`, `CapellaImporter`, `BinaryStylesheet`. `ScoreLoader` picks the right importer by extension/sniffing.
- `rendering/` — the engraving engine. `ScoreRenderer` orchestrates; layouts in `rendering/layout/` (`PageViewLayout`, `HorizontalScreenLayout`, `ParchmentLayout`) drive `BarRendererBase` subclasses in `rendering/` (`ScoreBarRenderer` standard notation, `TabBarRenderer` tabs, `NumberedBarRenderer` jianpu/numbered, `SlashBarRenderer`). Glyphs in `rendering/glyphs/`; effects band in `rendering/effects/`; jianpu helpers in `rendering/jianpu/`.
- `midi/` — MIDI generation (`MidiFileGenerator`) and tick→beat lookup (`MidiTickLookup`) for playback cursors.
- `synth/` — `AlphaSynth` SoundFont2/TinySoundFont synthesizer + `AlphaSynthWrapper` worker bridge and `BackingTrackPlayer`.
- `platform/` — abstraction over output targets: `ICanvas` with implementations in `platform/svg/`, `platform/skia/`, `platform/javascript/`; `IUiFacade` for host integration.
- `generated/` — **auto-generated**, do not edit. Serializers, JSON types, cloners.
- Entry points: `alphaTab.core.ts` (pure engine, no workers), `alphaTab.main.ts` (web entry, wires workers/worklets), `alphaTab.worker.ts`, `alphaTab.worklet.ts`.

### Settings
`Settings` (`src/Settings.ts`) is the central config, composed of `core`, `display`, `notation`, `importer`, `player`, `exporter` sub-objects. It is a `@json` class — JSON load/save round-trips through `SettingsSerializer`. `display.resources` (`RenderingResources`) holds fonts/colors; the theme system (`RenderingTheme.ts`) applies semantic color tokens onto resources. `Settings.songBook` is a preset.

### Testing architecture
- **Unit/importer tests** (`test/importer/`, `test/model/`, `test/xml/`, `test/zip/`) use chai + jest-snapshot via `test/mocha.jest-snapshot.ts`. Snapshots live in `test/**/__snapshots__/*.snap`. `PrettyFormat.ts` registers custom serializers for `Score`, MIDI events, alphaTex AST/diagnostics so snapshots are human-readable.
- **Visual tests** (`test/visualTests/`) use `VisualTestHelper` + `alphaskia` to rasterize and pixel-compare (`PixelMatch`). `test/visualTests/features/` covers notation features; `test/visualTests/issues/` regression-tests specific bug reports.
- `test/TestPlatform.ts` abstracts filesystem access so tests run on Node and other platforms.

## Conventions

- **Imports**: use the package name `@coderline/alphatab/...` (e.g. `import { Score } from '@coderline/alphatab/model/Score'`), not deep relative paths. Recent refactors replaced relative imports with package imports; match that style.
- **Naming** (enforced by biome `useNamingConvention`, `strictCase: false`): private class members are `_camelCase`; enum members are `PascalCase` or `CONSTANT_CASE`; static readonly class props allow `PascalCase`.
- **Generated files**: never hand-edit `src/generated/*`. Change the source `@json`/model class and re-run `generate-typescript`.
- **`@target web`** members must stay browser/Node-only — no logic that native targets depend on.
- Biome config excludes `dist`, `src/generated`, and `test-data` from lint/format.

## Workflow constraints (project-specific)

- Do not commit, push, tag, rebase, merge, or open PRs unless explicitly asked in the current turn. "Looks done" / "previous turn was committed" is not authorization. Finish in the working tree and report "done, awaiting your go-ahead to commit."
- Do not create branches unless explicitly asked; work on the current branch.
