# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

This is the **alphaTab monorepo** (`@coderline/alphatab-monorepo`, npm workspaces under `packages/*`). The core library lives in `packages/alphatab`; everything else consumes it. You are usually working inside `packages/alphatab`.

Key sibling packages:
- `packages/alphatab` — the rendering/synthesis engine (this package).
- `packages/transpiler` — TypeScript → C# / Kotlin source transpiler. Parses `src/` with the TS compiler and emits cross-platform code. Run via `generate-typescript`.
- `packages/tooling` — shared Vite build plugins and TS helpers (`elementStyleUsingTransformer`, `dtsPathsTransformer`).
- `packages/csharp`, `packages/kotlin` — consume transpiled output to build native alphaTab.
- `packages/playground`, `packages/vscode`, `packages/lsp`, `packages/monaco`, `packages/vite`, `packages/webpack` — dev tooling and integrations.

Branches: `develop` is the integration branch; PRs target `develop`.

## Common commands

All commands below run from `packages/alphatab` unless noted. Run from the repo root to use the monorepo-level wrappers.

### Build
```bash
npm run generate-typescript   # regenerate src/generated/* (Cloner, Serializer, JSON decls, VersionInfo) — DO NOT hand-edit generated files
npm run build                 # generate-typescript + vite build (ESM) + vite build (UMD)
npm run typecheck             # tsc --noEmit
npm run lint                  # biome lint
```
Build outputs go to `dist/`. The build copies `font/bravura/*` and `font/sonivox/*` into `dist/font` and `dist/soundfont`.

### Test
```bash
npm test                              # mocha (loads .env, runs test/**/*.test.ts via tsx)
npm test -- --grep "pattern"          # run a single test by name
npm test -- --grep "AlphaTexImporter" # run one test file's suite
UPDATE_SNAPSHOT=true npm test         # update jest snapshots (also: --updateSnapshot)
CI=true npm test                      # CI mode: snapshots are write-locked (update disabled)
```
`.mocharc.json` injects `test/global-hooks.ts` (sets up chai + jest-snapshot) and uses `tsx/esm` with `experimental-specifier-resolution=node`. Imports use the `@coderline/alphatab` package name (resolved via workspace), **not** deep relative paths — see the import style note below.

### Visual / reference tests
Visual tests render to a Skia canvas and pixel-compare against `.png` reference files in `test-data/visual-tests/`. On mismatch, the helper writes `<name>.new.png` and `<name>.diff.png` next to the reference. These artifacts are gitignored.
```bash
npm run test-accept-reference   # promote all *.new.png → *.png and delete *.diff.png (use after verifying a deliberate change)
```
Only run/accept visual references for rendering changes you intend to change; an unexpected `.new.png` means your change altered rendering.

### Regenerating code
Any change to a model/settings class annotated with `@json` requires `npm run generate-typescript` to regenerate serializers under `src/generated/`. The generated files start with an `<auto-generated>` header.

## Package layout (`packages/alphatab`)

Top-level directories (everything except `src/`):
- `src/` — TypeScript source. See "Source structure" below.
- `generated/` output is under `src/generated/` and is gitignored — do not edit; regenerate with `npm run generate-typescript`.
- `bundler/` — deprecated compatibility shims (`alphaTab.{vite,webpack}.{js,mjs,d.ts}`) that re-export the bundler plugins now living in `@coderline/alphatab-{vite,webpack}`. Each warns on import. Copied into `dist/` by `prepack` and exposed via `package.json` `exports` (`./vite`, `./webpack`).
- `scripts/` — build/codegen helpers. Two groups: (a) code-gen emitters driven by `@coderline/alphatab-transpiler` — `generate-typescript.ts` (entry), `EmitterBase.ts`, `TypeSchema.ts`, `CloneEmitter.ts`, `Serializer*.ts` (emits `*Serializer` with `fromJson`/`toJson`/`setProperty`), `JsonDeclarationEmitter.ts`; (b) build/release helpers — `prepack.mts` (prepares `dist/` for `npm pack`: flips `package.json` `type` to `commonjs`, copies README + bundler shims), `smufl-metadata.ts` (filters `bravura_metadata.json` to glyphs alphaTab uses, optionally rewrites glyph tables in `EngravingSettings.ts`), `accept-new-reference-files*.ts` (promote `*.new.png`).
- `font/` — bundled assets. Only `bravura/` (SMuFL music font: `Bravura.{eot,otf,svg,woff,woff2}` + `bravura_metadata.json`) and `sonivox/` (`sonivox.sf2`/`.sf3` SoundFont) are shipped, copied into `dist/font` and `dist/soundfont` by the vite build. Other subdirs (`noto-*`, `petaluma/`) are test-only fonts. `bravura_alphatab_metadata.json` is generated and gitignored.
- `test-data/` — test fixtures and references, organized by source format: `guitarpro{3..8}/`, `musicxml{3,4}/`, `musicxml-samples/`, `musicxml-testsuite/` (official W3C suite), `conversion/`, `lyrics/` (`.atex` = alphaTab text), `exporter/`, `audio/` (PCM/SF/OGG fixtures + expected outputs), `xml/`, and `visual-tests/` (14 feature subdirs each holding a source file + expected `.png`; mismatch artifacts `.new.png`/`.diff.png` are gitignored).
- `dist/` — build output (gitignored). UMD (`alphaTab.js`/`.min.js`), ESM multi-entry (`alphaTab.{core,worker,worklet}.{mjs,.min.mjs}`), bundled `alphaTab.d.ts`, copied `font/` + `soundfont/`.
- Root config: `package.json` (`type: module`; `exports` for `.`, `./vite`, `./webpack`, `./soundfont/*`, `./font/*`), `vite.config.ts` (UMD + ESM modes; `viteStaticCopy` for fonts; `elementStyleUsingTransformer` + `dtsPathsTransformer` from `../tooling`), `biome.jsonc` (lints everything except `dist`/`src/generated`/`test-data`; `useNamingConvention` with `strictCase:false`), `tsconfig.json` (just `extends ../../tsconfig.base.json`), `.mocharc.json` (injects `test/global-hooks.ts`, runs `tsx/esm` with `experimental-specifier-resolution=node`), `.env` (test env, 39B), `.gitignore`.

## Architecture

### Cross-platform transpilation model (read before editing public API)
alphaTab is authored once in TypeScript and transpiled to C# and Kotlin. Doc-comment annotations drive this and **must be respected**:
- `@target web` — marks members that are browser/Node-only (DOM, workers, audio worklets, `import.meta.url`). The transpiler **drops these from C#/Kotlin**; the TS build keeps them. When editing, treat `@target web` members as not existing on the native targets.
- `@partial` — marks a class whose declaration is split across multiple files (members merged by the transpiler). A `@partial` class in file A can have its members extended in file B. Do not collapse partial classes into single files.
- `@json`, `@json_strict`, `@json_on_parent`, `@json_partial_names`, `@json_add` — drive JSON (de)serialization codegen. `@json` classes get a generated `*Serializer` and `*Json` type in `src/generated/`. Adding/removing `@json` fields requires regenerating.
- `@public` vs `@internal` — `@public` marks the documented API surface (`Settings`, `Score`, `AlphaTabApiBase`, `ScoreRenderer`, `AlphaSynth`, `ScoreImporter`/`ScoreExporter`, `MidiFile`/`MidiTickLookup`, `BoundsLookup`, `ICanvas`/`IUiFacade`, the layouts). Everything else is `@internal`. The `generated/` tree is `@internal` but exposed transitively through JSON types.

If you add a public class member, consider whether it needs `@target web` (browser-only), whether the class is `@json` (then regenerate), and whether it should be `@public`.

### Source structure (`packages/alphatab/src`)

Every subdirectory ships a `_barrel.ts` (or `_jsonbarrel.ts`) and `alphaTab.core.ts` re-exports each as a namespace (`importer`, `io`, `exporter`, `midi`, `model`, `rendering`, `platform`, `synth`, `json`). **Always import via the package name `@coderline/alphatab/...` (a namespace path), never via deep relative paths.**

Top-level entry files:
- `alphaTab.core.ts` — cross-platform barrel re-exporting all public settings/model/io/midi/synth/rendering/platform symbols and sub-namespaces. The single import target for any consumer.
- `alphaTab.main.ts` — `@target web` main-thread entry. Re-exports core, then calls `Environment.initializeMain()` wiring the worker constructor (ESM/blob/script fallbacks) and audio-worklet `addModule` callback. The browser bundle entry.
- `alphaTab.worker.ts` — `@target web` web-worker entry. Imports core and calls `Environment.initializeWorker()` for off-thread rendering/synth.
- `alphaTab.worklet.ts` — `@target web` AudioWorklet entry. Imports core and calls `Environment.initializeAudioWorklet()` for off-thread audio synthesis.
- `alphaTab.polyfills.ts` — `@target web` side-effecting polyfills (ResizeObserver, IntersectionObserver, `Element.replaceChildren`, `String.replaceAll`); imported first by `alphaTab.core.ts`.
- `AlphaTabApiBase.ts` (~155KB) — platform-agnostic API orchestrating load → render → play with full event wiring; extended per-platform.
- Settings/API-surface files: `Settings.ts`, `CoreSettings.ts`, `DisplaySettings.ts`, `EngravingSettings.ts` (~88KB of spacing/thickness metrics), `NotationSettings.ts`, `PlayerSettings.ts`, `ImporterSettings.ts`, `ExporterSettings.ts`, `RenderingResources.ts` (fonts/colors), `RenderingTheme.ts` (semantic color tokens → resources), `Environment.ts` (runtime detection of web/worker/worklet, bundlers, font loading, render-engine factory registration), `SmuflMetadata.ts`, `LayoutMode.ts`, `StaveProfile.ts`, `Logger.ts`/`LogLevel.ts`, `EventEmitter.ts`, plus scroll/cursor (`ScrollHandlers.ts`, `CursorHandler.ts`) and event/error arg types.

Domain directories:

- `model/` — the music notation domain model, the public data surface almost everything else depends on. Hierarchy: `Score` → `Track` → `Staff` → `MasterBar`/`Bar` → `Voice` → `Beat` → `Note`, each with `*SubElement`/`*Style` enums for theming. Also `JsonConverter.ts` (`@public @target web`, delegates to `generated/`), `ModelUtils.ts` (MIDI↔frequency, tuning math), `MusicFontSymbol.ts` (SMuFL glyph enum used everywhere), `Tuning.ts`, `PercussionMapper.ts`, `RenderStylesheet.ts`/`ElementStyle.ts`, `BackingTrack.ts`, and the many notation enums (`Duration`, `KeySignature`, `Clef`, `BendType`, `BrushType`, `HarmonicType`, `VibratoType`, `WhammyType`, `GraceType`, `AccentuationType`, `AccidentalType`, `FadeType`, `CrescendoType`, `Ottavia`, `Fermata`, `TripletFeel`, `WahPedal`, `Rasgueado`, `BarreShape`, `GolpeType`, …).
- `importer/` — file format readers → `Score`. `ScoreImporter.ts` (`@public` base), `ScoreLoader.ts` (`@public @target web` async loader over XHR), `Gp3To5Importer.ts` (legacy binary), `Gp7To8Importer.ts`/`GpxImporter.ts` (zip-based, share `GpifParser.ts`), `MusicXmlImporter.ts` (uses `xml/`), `CapellaImporter.ts`/`CapellaParser.ts`, `AlphaTexImporter.ts` (delegates to `alphaTex/`). `BinaryStylesheet.ts`/`PartConfiguration.ts`/`LayoutConfiguration.ts` read/write the GP binary style/part/layout blobs (also reused by `exporter/Gp7Exporter`).
  - `importer/alphaTex/` — the alphaTex v1+ compiler: `AlphaTexLexer.ts` → `AlphaTexParser.ts` (`@public`) → `AlphaTexAst.ts`, with `AlphaTexShared.ts` (diagnostics/enums/state), the v1 language handler (`AlphaTex1LanguageHandler.ts` + `*EnumMappings`/`*Definitions` + `ATNF.ts`), `AlphaTex1MetaDataReader.ts` for streaming parse, and `IAlphaTexLanguageImportHandler.ts` extension point. AST types are public for programmatic generation/inspection.
- `exporter/` — `Score` → file format (counterpart to `importer/`). `ScoreExporter.ts` (`@public` base: `init`/`export`/`writeScore`), `Gp7Exporter.ts` (zips `score.gpif` XML + `BinaryStylesheet` + `PartConfiguration` + `LayoutConfiguration` via `ZipWriter`), `GpifWriter.ts`, `GpifSoundMapper.ts` (model sound → GP sound ids), `AlphaTexExporter.ts`. GP7/8 round-trips symmetrically with the importer.
- `io/` — low-level binary I/O primitives (no music knowledge): `IReadable.ts`/`IWriteable.ts` (stream abstractions), `ByteBuffer.ts` (growable default sink/source), `IOHelper.ts` (static BE/LE int/float/string readers & writers), `BitReader.ts` (packed/compressed formats), `JsonHelper.ts` (JSON traversal for generated serializers), `TypeConversions.ts`.
- `xml/` — self-contained XML DOM + parser + writer (Haxe-stdlib-derived, MIT) used by MusicXML, Capella, and GP `score.gpif`. `XmlDocument.ts`/`XmlNode.ts`/`XmlParser.ts`/`XmlWriter.ts`/`XmlError.ts`. `@internal`, no dependency on the model.
- `zip/` — pure-TS ZIP (deflate/inflate) for GP `.gp`/`.gpx` and zipped formats. `ZipReader.ts`/`ZipWriter.ts`/`ZipEntry.ts`, plus the DEFLATE codec (`Inflate.ts`/`Deflater.ts` + `*Huffman*`/`PendingBuffer`) and checksums (`Crc32.ts`/`Adler32.ts`). `@internal`, depends only on `io/`.
- `midi/` — builds a MIDI file model from a `Score` and exposes tick→beat lookups. `MidiFileGenerator.ts` (`@internal`, walks a `Score` emitting events through `IMidiFileHandler`), `MidiFile.ts`/`MidiTrack.ts`/`MidiEvent.ts` (`@public` SMF model), `MidiTickLookup.ts`/`MasterBarTickLookup.ts`/`BeatTickLookup.ts` (`@public` time→beat index for cursor/playback), `MidiPlaybackController.ts` (repeat/jump/section navigation), `GeneralMidi.ts`/`ControllerType.ts`/`MidiUtils.ts`, `AlphaSynthMidiFileHandler.ts` (feeds the synth). Boundary layer between model and synth.
- `synth/` — audio synthesizer/player orchestrator. `AlphaSynth.ts` (`@public`, wires `MidiFileSequencer` + `TinySoundFont` + `ISynthOutput`), `IAlphaSynth.ts`/`ISynthOutput.ts` (`@public`), `MidiFileSequencer.ts` (`@internal`), `BackingTrackPlayer.ts`, `ExternalMediaPlayer.ts` (`IExternalMediaHandler`), `IAudioExporter.ts`/`IAudioSampleSynthesizer.ts` (offline export), `AlphaSynthWrapper.ts`, plus player event-arg/state types. DSP lives in subdirs:
  - `synth/ds/` — lock-free hot-path data structures: `Queue.ts`, `CircularSampleBuffer.ts` (ring buffer bridging synth↔output thread).
  - `synth/soundfont/` — SF2/SF3 parser: `Hydra.ts` (loads PBAG/PGEN/PHDR/IBAG/IGEN/INST/SHDR chunks, decodes samples — PCM directly, vorbis via `vorbis/`), `RiffChunk.ts`.
  - `synth/synthesis/` — the TinySoundFont port (MIT): `TinySoundFont.ts` (engine: presets/channels/voice scheduling), `Voice.ts`/`VoiceEnvelope.ts`/`VoiceLfo.ts`/`VoiceLowPass.ts` (per-voice DSP), `Channel.ts`/`Channels.ts`, `Preset.ts`/`Region.ts`, `SynthEvent.ts`.
  - `synth/vorbis/` — pure-TS Ogg/Vorbis decoder for SF3 sample data: `VorbisFile.ts` → `OggReader.ts` → `VorbisStream*` stages → `IntBitReader.ts`. Consumed only by `Hydra.ts`.
- `rendering/` — the engraving engine: `Score` → positioned `Glyph`s on staves. `ScoreRenderer.ts` (`@public`, owns canvas + layout, builds `BoundsLookup`), `BarRendererBase.ts` (`@internal` staff-segment base), concrete renderers `ScoreBarRenderer.ts` (standard notation) / `TabBarRenderer.ts` (guitar tab) / `SlashBarRenderer.ts` / `NumberedBarRenderer.ts` (jianpu), each with a `*Factory.ts`, plus `LineBarRenderer.ts`, `EffectBand*.ts`/`EffectInfo.ts`/`EffectBandContainer.ts`, and `RenderFinishedEventArgs.ts`/`IScoreRenderer.ts`. Subdirs:
  - `rendering/layout/` — layout engines: `ScoreLayout.ts` (`@internal` base), `PageViewLayout.ts`/`HorizontalScreenLayout.ts`/`ParchmentLayout.ts` (`@public`, selectable via `Settings.layout`), `VerticalLayoutBase.ts`, `SlurRegistry.ts`.
  - `rendering/staves/` — staff/system geometry (`@internal`): `StaffSystem.ts`, `StaffTrackGroup.ts`, `RenderStaff.ts`, `MasterBarsRenderers.ts`, `Spring.ts`/`BarLayoutingInfo.ts` (spring-rod spacing model).
  - `rendering/glyphs/` — the drawable symbol vocabulary (~95 files, `@internal`): `Glyph.ts` base, `NoteHeadGlyph`/`AccidentalGlyph`/`FlagGlyph`/`ClefGlyph`/`TimeSignatureGlyph`, tab glyphs (`TabNoteChordGlyph`/`TabBendGlyph`/`TabClefGlyph`), score articulations (`ScoreSlurGlyph`/`ScoreTieGlyph`/`ScoreBendGlyph`/`ScoreWhammyBarGlyph`), jianpu glyphs (`NumberedNoteHeadGlyph`/`NumberedBeatGlyph`/`NumberedTieGlyph`), plus `ChordDiagramGlyph`/`BarTempoGlyph`/`LyricsGlyph`/`TextGlyph`.
  - `rendering/effects/` — `EffectInfo` subclasses, one per `NotationElement` (~40 files, `@internal`): `TempoEffectInfo`, `LyricsEffectInfo`, `ChordsEffectInfo`, `DynamicsEffectInfo`, `NoteEffectInfoBase`, etc.
  - `rendering/utils/` — bounds bookkeeping (hit-testing/cursor) + engraving helpers: `BoundsLookup.ts` (`@public` root of `StaffSystemBounds`/`MasterBarBounds`/`BarBounds`/`BeatBounds`/`NoteBounds`, has `toJson()`), `BeamingHelper.ts`/`BeamingRuleLookup.ts`/`BeamDirection.ts`, `AccidentalHelper.ts`, `BarCollisionHelper.ts`/`BarHelpers.ts`, `ElementStyleHelper.ts` (emits CSS-style class tokens for theming).
  - `rendering/jianpu/simpleNotation/` — jianpu helpers adapted from the MIT `simple-notation` project: `groupNotesForBeam.ts`, `buildJianpuDrawNotes`/`durationUtils.ts`, `drawNoteGlyph.ts`/`drawUnderlines.ts`/`drawTieLine.ts`/`drawLyric.ts`, `parseJianpuText.ts`. Re-exported via the rendering barrel; consumed by `model/Bar.ts` and the numbered renderers.
- `platform/` — abstractions decoupling rendering/UI from any runtime. `ICanvas.ts` (`@public` drawing surface), `IUiFacade.ts` (`@public` UI abstraction), `IContainer.ts`/`IMouseEventArgs.ts`, `Cursors.ts` (`@public` bar/beat/selection cursor wrapper), `Json.ts`. Concrete `@target web` impls live in subdirs:
  - `platform/javascript/` — browser impls (`@target web`): `AlphaTabApi.ts` (`@public`, extends `AlphaTabApiBase` with an `HTMLElement`), `BrowserUiFacade.ts`, `Html5Canvas.ts`, `AlphaTabWebWorker.ts`/`AlphaTabWorkerScoreRenderer.ts` (worker renderer proxy), `AlphaSynthWebWorkerApi.ts`/`AlphaSynthWebWorker.ts` (synth worker bridge), `AlphaSynthAudioWorkletOutput.ts`/`AlphaSynthScriptProcessorOutput.ts`/`AlphaSynthWebAudioOutputBase.ts`, `JQueryAlphaTab.ts`, polyfills (`ResizeObserverPolyfill.ts`/`IntersectionObserverPolyfill.ts`), `WebPlatform.ts`. Almost everything is `@target web`.
  - `platform/skia/` — `SkiaCanvas.ts` (`@target web @internal`) delegating to `@coderline/alphaskia`; loaded dynamically when `Environment` selects the Skia engine (server/native high-quality rendering).
  - `platform/svg/` — SVG-string backends + font-metric tables: `SvgCanvas.ts` (`@internal` base), `CssFontSvgCanvas.ts` (`@public`, CSS web fonts), `FontSizes.ts` (`@public` glyph/text width tables for font-less metrics). Default off-screen/server render engine. Note: Skia is wired via `Environment`, not the platform barrel.
- `generated/` — **auto-generated, do not edit.** Two clearly separated concerns: top-level `generated/` holds serializers/JSON types/cloners for the **settings** hierarchy (`CoreSettings`, `DisplaySettings`, `EngravingSettings`, `NotationSettings`, `ImporterSettings`, `ExporterSettings`, `PlayerSettings`, `RenderingResources`, `Settings`, slide/vibrato playback settings) plus `VersionInfo.ts` (build metadata consumed as `meta`) and `_jsonbarrel.ts` (re-exports `*Json` types as the `json` namespace). `generated/model/` holds serializers/cloners for the **model** classes (`ScoreSerializer` composing `MasterBar`/`Track`/`Staff`/`Bar`/`Beat`/`Voice`/`Note`/`Chord`/`Automation`/`BendPoint`/`Tuning`/etc.), consumed by `JsonConverter.ts` and the worker IPC boundary. Change the source `@json`/model class and re-run `generate-typescript`.

### Settings
`Settings` (`src/Settings.ts`) is the central config, composed of `core`, `display`, `notation`, `importer`, `player`, `exporter` sub-objects. It is a `@json` class — JSON load/save round-trips through `SettingsSerializer`. `display.resources` (`RenderingResources`) holds fonts/colors; the theme system (`RenderingTheme.ts`) applies semantic color tokens onto resources. `Settings.songBook` is a preset.

### Testing architecture
- **Unit/importer tests** (`test/importer/`, `test/model/`, `test/xml/`, `test/zip/`) use chai + jest-snapshot via `test/mocha.jest-snapshot.ts`. Snapshots live in `test/**/__snapshots__/*.snap`. `PrettyFormat.ts` registers custom serializers for `Score`, MIDI events, alphaTex AST/diagnostics so snapshots are human-readable.
- **Visual tests** (`test/visualTests/`) use `VisualTestHelper` + `alphaskia` to rasterize and pixel-compare (`PixelMatch`). `test/visualTests/features/` covers notation features; `test/visualTests/issues/` regression-tests specific bug reports.
- `test/TestPlatform.ts` abstracts filesystem access so tests run on Node and other platforms.

## Conventions

- **Imports**: use the package name `@coderline/alphatab/...` (e.g. `import { Score } from '@coderline/alphatab/model/Score'`), not deep relative paths. Recent refactors replaced relative imports with package imports; match that style.
- **Naming** (enforced by biome `useNamingConvention`, `strictCase: false`): private class members are `_camelCase`; enum members are `PascalCase` or `CONSTANT_CASE`; static readonly class props allow `PascalCase`.
- **Generated files**: never hand-edit `src/generated/*`. Change the source `@json`/model class and re-run `generate-typescript`.
- **`@target web`** members must stay browser/Node-only — no logic that native targets depend on.
- Biome config excludes `dist`, `src/generated`, and `test-data` from lint/format.
